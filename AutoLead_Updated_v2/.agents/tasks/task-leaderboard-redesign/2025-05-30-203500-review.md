# Competitive leaderboard with glassmorphism redesign

The rankings API now generates personalized competitive remarks that tell each agent how many points they need to overtake the person directly above them (by name), replacing generic motivational text. Both the admin and agent panels received a glassmorphism leaderboard design with animated gradient borders, a 3D-elevated podium for the top 3, ring-glow profile photos, and shimmer effects. The leaderboard was repositioned to appear prominently near the top of both views.

**Watch for:** The score formula double-counts `interested` and `followup` dispositions because `totalCalls` already includes them (confirmed). The admin page has no responsive breakpoint for the podium, unlike the agent page (confirmed). Remarks wording ("You need N more points — try getting more interested leads!") is numerically misleading due to the double-counting (confirmed).

## High-level view

The remarks logic identifies the agent directly above in rank and computes the score delta, handling first place, tied scores, and negative scores. The score formula `(interested + followups + totalCalls) - notInterested` effectively double-weights quality outcomes because `totalCalls` already includes interested/followup calls. A single "interested" call contributes +2 points, while a "not_interested" call contributes 0. This means the "points needed" in remarks doesn't map to a simple action like "get N more interested leads" — that remark suggests N interested leads are needed when actually only ceil(N/2) would suffice.

The CSS and rendering JS are copy-pasted between both pages (~60 lines of styling, ~50 lines of render logic). The agent page includes a responsive breakpoint that stacks podium cards vertically below 900px; the admin page omits this rule, which will cause awkward wrapping on narrow screens.

## Score formula and double-counting

The formula `(interested + followups + totalCalls) - notInterested` yields the following per-disposition impact:

- `interested` call: +1 (interested) + 1 (totalCalls) = **net +2**
- `followup` call: +1 (followups) + 1 (totalCalls) = **net +2**
- `not_interested` call: +1 (totalCalls) - 1 (notInterested) = **net 0**
- `dead` / `not_received` / `switch_off`: +1 (totalCalls) = **net +1**

Neutral dispositions (dead, not received, switch off) still contribute +1 each, which rewards call volume even when outcomes are poor. The remark text says "Try getting more interested leads!" but each interested lead is worth 2 points, not 1 — so "You need 6 more points" actually means "3 interested leads" or "6 dead calls," which is a confusing signal to agents trying to climb.

## Remarks edge case at zero

When multiple agents are tied at score 0 and one is ranked #2, the remark says "Tied with [name] at #1! One more interested lead will push you ahead!" — technically accurate but produces motivational text for agents who haven't started working yet. This won't break anything but may feel odd in practice.

Agent names in remarks originate from admin-controlled data (`appState.agents[id].name` or the EID registry). The client applies `escapeHtml()` to `r.remarks`, so even if a name contained angle brackets, XSS is prevented. The server sends raw strings without sanitization, which is acceptable given the trusted input source.

## Missing responsive rule in admin

The agent page has:
```css
@media(max-width:900px){
  .leaderboard-podium{flex-direction:column;align-items:center}
  .podium-card{min-width:auto;width:100%}
}
```

The admin page's only media query is:
```css
@media(max-width:900px){ .stats-grid{grid-template-columns:1fr 1fr} .grid-2{grid-template-columns:1fr} }
```

On mobile-width admin views, the podium cards (160px min-width each) will try to fit three in a row. With `flex-wrap: wrap`, they'll eventually wrap, but without `flex-direction: column` the transition is less graceful — cards may wrap at two-and-one instead of cleanly stacking.

## Duplicated CSS and JS between pages

The leaderboard CSS and rendering JS are copy-pasted between `agent/index.html` and `admin/index.html`, differing only in function names and DOM element IDs. Any future styling or logic fix must be applied in both places — and as the missing responsive rule demonstrates, this duplication has already led to a divergence.

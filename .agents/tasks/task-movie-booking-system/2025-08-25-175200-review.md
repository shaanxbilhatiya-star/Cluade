# Movie booking system — v2 review (post-fix pass)

The v1 review raised 7 issues. Five have been adequately fixed: XSS protection via `escapeHTML()` covers the main render paths, ticket tabs now filter by date/status and pills filter by type, the hardcoded phone number is replaced with localStorage-backed input, the body parser properly destroys the stream on oversize, and file writes use atomic temp-file-then-rename. Two remain partially or wholly unaddressed: the write lock mechanism exists as dead code (never called), and `renderTimeSlots` plus `generatePosterSVG` still inject server data into innerHTML without escaping.

Watch for: Residual XSS in `renderTimeSlots()` where `s.time`, `s.cinema`, `s.screen`, and `s.id` are interpolated without `escapeHTML()` (confirmed). The `generatePosterSVG` function injects `title` and `genre` directly into SVG `<text>` elements without escaping (confirmed). The `acquireLock`/`releaseLock` mechanism is defined but never invoked — concurrent booking requests can still double-sell seats (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The atomic write fix (temp file + `renameSync`) prevents file corruption from torn writes, but the actual double-sell race remains because the lock mechanism on lines 35–57 is never called from any handler. Two concurrent `POST /api/bookings` requests for the same seat will both pass the `alreadyBooked` check before either writes the updated showtime file.

The XSS remediation covers the majority of render paths, but `renderTimeSlots()` interpolates `s.time`, `s.cinema`, `s.screen`, and `s.id` directly into the HTML template, and `generatePosterSVG` passes `title` and `genre` into SVG `<text>` elements unescaped. Since showtimes and movies are created through the unauthenticated API, these remain stored XSS vectors.

## Residual XSS in time slot and poster rendering

The `renderTimeSlots` function on line 2162 builds HTML from showtime data without escaping:

```javascript
grid.innerHTML = showtimes.map(s => `
    <div class="time-slot" onclick="selectTimeSlot('${s.id}', this)">
        <div class="time-text">${s.time}</div>
        <div class="time-cinema">${s.cinema} - ${s.screen}</div>
    </div>
`).join('');
```

Since `POST /api/showtimes` accepts arbitrary `cinema` and `screen` strings without auth, an attacker can create a showtime with `cinema: "<img src=x onerror=alert(1)>"` and it executes when any user views that movie's time slots. The same applies to `s.id` inside the `onclick` attribute — a crafted ID containing a single-quote breaks out of the JavaScript string context.

Similarly, `generatePosterSVG` interpolates `title` and `genre` directly into SVG text elements:

```javascript
<text ...>${title.length > 14 ? title.substring(0, 12) + '..' : title}</text>
<text ...>${genre}</text>
```

Inside an SVG rendered via innerHTML, a title like `</text><foreignObject><body><script>alert(1)</script></body></foreignObject><text>` can escape the text element. The fix is trivial — wrap both with the existing `escapeHTML()` function.

The success screen (line 2407) also interpolates `s.time` and `s.endTime` without escaping, though this is lower risk since it only appears after a user has already selected that showtime.

## Dead write lock and seat double-sell

The server defines `acquireLock` and `releaseLock` (lines 35–57) with a promise-chaining strategy, but neither function is ever called. The booking handler `handleCreateBooking` (line ~310) reads `showtimes.json`, checks seat availability, then writes the updated file — all without holding any lock. Under concurrent requests:

1. Request A reads showtimes, sees seat A1 available
2. Request B reads showtimes, sees seat A1 available  
3. Request A writes A1 to bookedSeats
4. Request B writes A1 to bookedSeats (clobbering A's write via atomic rename)

The atomic write prevents file corruption (partial JSON) but doesn't prevent the logical race. For a local demo this is unlikely to trigger from manual UI interaction, but the API is exposed and can be hit programmatically. Wrapping the read-check-write in `await acquireLock('showtimes.json')` and calling `releaseLock` afterward would close it.
